# 감자마켓 실습 커리큘럼 (8단계)

> orca orchestration 강의 실습용 프로젝트. 당근마켓의 역발상 — 구매자가 사고 싶은 물건과 희망 가격을 올리면 판매자들이 줄을 서는 구조.


| #   | 단계             | 구현 내용                                                                 |
| --- | -------------- | --------------------------------------------------------------------- |
| 1   | 프로젝트 기반        | 로그인 없이 볼 수 있는 간단한 웹. Next.js 스캐폴딩 + 목업 데이터로 화면만 구성. Supabase/DB 연동 없음 |
| 2   | 회원가입·로그인      | 이메일·비밀번호만 입력하고, 이메일이 중복되지 않으면 즉시 가입 완료. FastAPI 로그인·로그아웃 구현. Supabase Auth와 이메일 인증은 사용하지 않음 |
| 3   | 구매요청 등록&amp;탐색 | 구매자가 원하는 물건+희망가 등록, 목록 조회. front/backend 결과물 통합 지점                    |
| 4   | 사진 등록          | Supabase Storage 연동, 구매요청에 사진 첨부                                      |
| 5   | 판매자 지원 처리      | 판매자 N명이 동시 지원 → 지원 건마다 채팅방 자동 생성(병렬 처리 후 N개 상태로 수렴)                   |
| 6   | 구매자-판매자 채팅     | 폴링 기반(3~5초) 채팅으로 구매자-판매자 협의. 워커 간 직접 통신으로 시연                          |
| 7   | 매칭 확정&amp;상태관리 | 구매자가 여러 채팅 중 1명 확정 → 나머지 자동 마감 처리                                     |
| 8   | 거래완료&amp;후기    | 거래 완료 처리, 후기 작성 (캡스톤)                                                 |


## 설계 원칙 요약

- **1단계는 로그인 없이 보는 화면만**: Supabase/DB/회원 기능을 제외하고 목업 데이터로 레이아웃·페이지 구조만 완성. 2단계에서 처음 회원 테이블과 FastAPI 회원 API를 도입해 난이도를 단계적으로 올림
- **지원(5) → 채팅(6) → 매칭(7) 순서**: 매칭이 채팅을 만드는 게 아니라 채팅의 결과가 매칭을 결정
- **3단계**는 front+backend 산출물이 처음 맞물리는 지점이라 검증자(게이트) 패턴을 배정. TDD의 RED-GREEN 자체 루프(구현자의 self-loop)와는 별개로, 독립된 리뷰 게이트(다른 세션이 diff를 보고 판정)를 둠
- **회원가입 입력은 이메일·비밀번호만**: 구매자/판매자 역할이나 프로필은 받지 않고, 정규화 이메일 중복만 검사해 즉시 계정을 생성
- **Supabase Auth 미사용**: 이메일 인증, 인증 메일, OAuth를 제외하고 FastAPI와 애플리케이션 회원 테이블로 가입·로그인·로그아웃을 구현
- **실시간 알림 대신 폴링 채팅** 채택 — 난이도 조절
