# 표시 이름 고유성 및 기존 사용자 보정

## 결정

`app_users.display_name`은 사용자에게 보이는 식별자이므로 중복을 허용하지 않는다.

## 적용 방식

- 신규 가입은 데이터베이스의 `UNIQUE (display_name)` 제약으로 최종 보장한다.
- 동일한 표시 이름으로 가입하면 API는 `409 display_name_already_exists`와 안내 문구를 반환한다.
- 기존 행은 마이그레이션에서 `감자-<사용자 UUID>` 형식으로 채운 뒤 `NOT NULL`, 길이, 고유성 제약을 적용한다.
- UUID 기반 값은 기존 사용자끼리 충돌하지 않으며 40자 제한 안에 들어간다.

## 검증

- 중복 가입 API 계약과 프런트엔드 오류 메시지를 테스트한다.
- 기존 DB 적용 뒤 전체 사용자 수, 채워진 표시 이름 수, 고유 값 수가 일치하는지 확인한다.
