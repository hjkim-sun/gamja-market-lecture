# PRD: 1단계 — 프로젝트 기반 (로그인 없이 보는 웹)

## 1. 배경 및 목적

감자마켓은 당근마켓의 역발상 서비스다 — 판매자가 물건을 올리는 대신, **구매자가 사고 싶은 물건과 희망 가격을 올리면 판매자들이 지원(줄서기)하는 구조**다.

1단계는 이 서비스의 첫 화면 뼈대를 만드는 단계다. 아직 인증도, 데이터베이스도 없다. **오직 화면 구조와 레이아웃만** 목업 데이터로 완성해서, 이후 단계에서 실제 데이터(Supabase)를 하나씩 연결해 나갈 기반을 마련한다.

## 2. 목표

- 로그인하지 않은 방문자가 서비스 컨셉과 현재 등록된 구매요청들을 둘러볼 수 있다.
- 이후 단계(인증, 등록, 채팅 등)가 이어 붙을 수 있는 라우팅/레이아웃 구조를 미리 확정한다.
- 백엔드/DB 없이도 화면이 완결된 상태로 동작한다 (목업 데이터).

## 3. 범위

### 포함 (In Scope)
- Next.js(App Router, TypeScript) 프로젝트 초기 세팅
- 공통 레이아웃: 헤더, 네비게이션, 푸터
- 랜딩 페이지: 서비스 소개 (감자마켓 컨셉 설명)
- 구매요청 목록 페이지: 목업 데이터 카드 나열
- 구매요청 상세 페이지: 목업 데이터 1건 상세 뷰
- 반응형 레이아웃 (모바일/데스크탑)
- 로그인/회원가입 진입 버튼 — UI만 존재, 클릭 동작 없음(또는 "준비 중" 표시)

### 제외 (Out of Scope)
- Supabase 연동 전체 (Auth / Postgres / Storage) — 2단계로 이연
- 실제 로그인/회원가입 로직
- 폼 제출, 데이터 저장/수정/삭제 로직
- API 라우트, 서버 상태 관리
- 검색/필터/정렬 등 목록 조작 기능

## 4. 사용자 스토리

- 방문자로서, 로그인 없이 사이트에 들어가서 감자마켓이 어떤 서비스인지 바로 이해하고 싶다.
- 방문자로서, 현재 어떤 구매요청들이 올라와 있는지 목록으로 훑어보고 싶다.
- 방문자로서, 관심 가는 구매요청을 클릭해서 상세 내용(원하는 물건, 희망 가격 등)을 보고 싶다.

## 5. 기능 요구사항

| ID | 요구사항 |
|---|---|
| F1 | `/` 경로에서 랜딩 페이지가 렌더링된다. 서비스명, 한 줄 설명(구매자가 물건과 희망가를 올리면 판매자가 지원한다는 컨셉)을 포함한다 |
| F2 | `/requests` 경로에서 구매요청 목록이 카드 형태로 렌더링된다. 각 카드는 제목, 희망 가격, 상태(예: 모집중)를 표시한다 |
| F3 | `/requests/[id]` 경로에서 특정 구매요청의 상세 정보가 렌더링된다 |
| F4 | 모든 페이지에 공통 헤더(로고/서비스명, 네비게이션)와 푸터가 적용된다 |
| F5 | 헤더에 로그인/회원가입 진입 버튼이 있으나, 클릭해도 실제 인증 동작은 없다 |
| F6 | 목업 데이터는 최소 5건 이상의 구매요청을 포함한다 (제목, 희망가, 상태, 등록일 등 필드 포함) |

## 6. 비기능 요구사항

- Supabase 등 외부 서비스에 대한 네트워크 호출이 코드 어디에도 존재하지 않는다 (완전 정적/목업 렌더링)
- 데스크탑(≥1024px)과 모바일(≤480px) 두 뷰포트에서 레이아웃이 깨지지 않는다
- TypeScript strict 모드 기준 타입 에러 없음

## 7. 수용 조건 (Acceptance Criteria)

- [ ] 로그인 없이 `/`, `/requests`, `/requests/[id]` 세 경로에 접근할 수 있다
- [ ] `/requests`에 목업 구매요청이 카드 목록으로 표시된다 (최소 5건)
- [ ] 목록의 카드를 클릭하면 해당 항목의 상세 페이지로 이동한다
- [ ] 상세 페이지에 목록에서 봤던 제목/희망가와 일치하는 정보가 표시된다
- [ ] 모든 페이지에 동일한 헤더/푸터가 적용되어 있다
- [ ] 코드베이스 내 Supabase/DB/API 호출 관련 코드가 없다
- [ ] 존재하지 않는 `/requests/[id]`로 접근 시 적절한 404 또는 안내 화면이 뜬다

## 8. 향후 단계와의 연결 지점

- 2단계에서 헤더의 로그인/회원가입 버튼에 실제 Supabase Auth 동작이 붙는다
- 3단계에서 `/requests`, `/requests/[id]`의 목업 데이터가 실제 DB 데이터로 교체된다 (라우트/컴포넌트 구조는 최대한 유지)
