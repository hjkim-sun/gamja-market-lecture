# 강의 주제

내가 orca에 대한 강의를 찍을 건데, orchestration 스킬을 이용한 오케스트레이션이 메인 주제가 될거야.

# 강의 방식
실습을 위주로 진행할건데 가장 중요한건 클로드코드와 codex 2가지 에이전트를 사용할거야.
그래서 서브에이전트를 구성해서 어떻게 오케스트레이션 하냐가 제일 중요한 관건이야.
내가 알기로 클로드코드는 subagent가 기본 team 모드로 수행되며 subagent간 통신이 가능하다는 것이 가장 큰 장점이야. 
반면에 codex는 아직 subagent가 메인에이전트하고만 통신이 가능해. 
이런 상황에서 어떤 다양한 시나리오로 오케스트레이션을 할 수 있는지를 보여줄 수 있을까가 가장 중요해.

# 실습 
## 컨셉
우선 비개발자가 바이브코딩으로 서비스를 개발해보며 orca의 오케스트레이션을 이용해서 어떻게 더 효율적으로 개발할 것인지 보여주는게 핵심이야. 
개발은 풀스택으로 진행될거야 (웹은 vercel에 배포, DB는 supabase, 로그인은 간단히 이메일/패스워드로 인증하는 정도)

## 현재 구상중인 실습 방식
스펙주도개발과 TDD를 접목해서 개발하는 과정을 보여주고 싶고 이 단계에서 서브에이전트 구성 & orca orchestration을 이용해서
개발하는 과정을 설명해주는게 핵심이야. 

# 확인해야 할 사항 
## 서브 에이전트 구성
따라서 서브 에이전트를 어떻게 구성할 건지가 중요해. 
예를 들어 front-designer, api-designer, front-developer, api-developer, tester
이렇게 구성할 수 있어. 
하지만 TDD를 제대로 하려면 developer 역할 외에 refactor도 필요한지 의문이야. 
그리고 front-refactor, api-refactor도 나눠야할까? 이런것도 고민이야. 
또한 orca에는 이슈나 pr을 가져와 처리하는 기능이 있는데 
이 단계에서 pr을 처리하기 위해 security-reviewer, code-refactor 같은 서브에이전트를 둬야 할까? 
refactor 역할을 가진 서브에이전트 역할은 아까 위에서 정의했으니 그걸 써도 될 것 같은데..

## 서브 에이전트 구성의 주의사항 
orca orchestration은 모든 단계를 메인 세션(오케스트레이터)가 중재해. 
그래서 강의 방식 부분에도 설명했지만 여러 시나리오로 오케스트레이션을 보여줘야 하는데
메인 세션이 워커로 클로드코드 세션, codex 세션을 띄울 수 있단 말이지? 
근데 클로드코드는 지시함에 따라 그 안에서 또 팀모드르 돌게끔 지시할 수 있을거야. 햐지만 codex는 그게 안되지. 
그래서 어떤 다양한 케이스로 오케스트레이션을 보여줄 수 있을지 조사가 필요해. 
방금 설명한 걸 그려보면 아래와 같아. 


메인 세션 ----> 클로드코드 세션 ---> 다수 팀모드 서브 에이전트 구동 
        |---> codex 세션1
        |---> codex 세션2
        |---> codex 세션3

이렇게 구성한다면 메인 세션은 워커 4개랑 통신하는 구조가 될거야. 
이 구조는 클로드코드 세션에는 서로 통신해야 하는게 적합한 작업을 몰아주고, codex 세션1,2,3은 뭘 시키면 좋을까? 고민도 필요해. 
아니면 이런 구조도 가능해 .

메인 세션 ----> 클로드코드 세션(팀모드) ----> codex 검토(게이트) ---> 종료
                      ^-------- 재지시---------|

이런 구조도 가능할거야. 이 경우 codex는 security 점검, 혹은 어떤 어떤 역할? 이 있겠지? (어떤 시나리오가 있을까?)

# 조사해야할 것
그래서 조사해야할 것은 이거야.
1. orca orchestration을 이용해 어떤 모양의 오케스트레이션 패턴이 가능할지 조사.
2. 그리고 각 패턴을 언제 쓰면 좋을지
3. 결과적으로 이 패턴을 위해 서브에이전트를 클로드코드와 codex에 어떻게 구성하면 좋을지
